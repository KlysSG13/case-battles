# ⚔️ Кейс-баттлы — Telegram Mini App

Образовательная платформа «строительство под давлением»: короткие раунды 3–10 минут в пяти
режимах, соперники (AI и реальные люди), рейтинг с лигами, публичная галерея лучших ответов,
синт-дрон-компаньон и награды. Классика (кейс → таймер → ответ → оценка ИИ по рубрике) сохранена
без изменений механики.

**Навигация (v1.1.0):** хаб с тремя первичными действиями (продолжить / новый заход / дуэли)
и пошаговый визард **Сфера → Режим → Игра** со степпером 1/2/3 — до старта любого режима
не больше 3 тапов. Питомец-дрон, бейджи, история и настройки — на втором уровне (профиль).

**Режимы:** 📘 Классика (4 мин, hard-банк из БД) · 🏗️ Конструктор бизнеса (8 мин, AI-сценарий
с ресурсами и 3 правилами) · 🚨 Спасение (6 мин, core) · 🎤 Питч инвестору (4 мин, core,
крючок→проблема→решение→рынок→ask) · ⚔️ Дуэли (AI-соперник в 3 стилях, hard-банк, асинхронные
PvP-вызовы по ссылке). Сложность режимов разделена на профили: **hard** (классика/дуэли —
банк не меняется) и **core** (спасение/питч/конструктор — лёгкие одношаговые кейсы 10–15 секунд
на решение, подсказка механики на экране раунда, `lib/content/core.ts`).
Модификатор «Три попытки»: зачёт по лучшей. Сложность: таймер ×1.2/×1.0/×0.8,
рейтинг-очки ×0.8/×1.0/×1.3. Free-квота в раундах: раунд с 3 попытками = 1 из 3 за сутки.

**Подача заданий (v1.1.0):** стена текста запрещена — задания рендерятся структурными блоками
(заголовок → контекст → пункты → таблица → вопрос) через `TaskContent`; таблицы — настоящий
табличный компонент (зебра, моно-цифры). Старые записи из БД автоматически разбираются
фолбэк-парсером (`lib/task-blocks.ts`). На экране вопроса — CSS-only анимации рамки/заголовка
(typewriter, сканлиния, глитч, градиентная кромка) с поддержкой `prefers-reduced-motion`.

**Монетизация (v1.2.0, Telegram Stars/XTR):** PRO-подписка на 30 дней (безлимит раундов,
3 подсказки в день, PRO-скин и бейдж), пачки подсказок (наводка на линию мышления, не победа),
косметика дрона (3 платных скина, PRO-скин «Квант», скины за уровни 5/10, аура «Гало»).
Цены — только в `lib/catalog.ts` на сервере; зачисления — только из вебхука
`successful_payment`, идемпотентно по `telegramPaymentChargeId`; инвойсы через
`createInvoiceLink` (XTR, provider_token пустой) и `WebApp.openInvoice`; возвраты —
`npm run stars:refund`. Колонка `isPro` удалена — единственный источник истины
`proUntil` (`lib/entitlements.ts`). PvP-дуэли — без подсказок (честность).

**Визуал:** тёмный терминал с неоном; единый модуль дизайн-токенов `lib/design-tokens.ts`
(цвета сфер/лиг/шкалы процентов) + `@theme` в globals.css — hex-коды вне файлов токенов
запрещены и отсутствуют. Синт-дрон — чистый SVG/CSS (парение, вращение сопел, пульс сенсора,
happy/sleep/glitch, уровень зарядом ядра).

**Стек:** Next.js 16 (App Router) + TypeScript · Tailwind CSS 4 · shadcn-стиль UI-компоненты ·
Prisma 6 + SQLite (схема переносима на PostgreSQL, миграции `pg:*`) · Telegram Bot API
(webhook, чистый fetch) · LLM через `z-ai-web-dev-sdk`.

## Быстрый старт (3 команды)

```bash
npm install
npm run db:seed     # 3 домена, 15 кейсов, 73 критерия, 12 бейджей (идемпотентно)
npm run dev         # http://localhost:3000
```

Откройте http://localhost:3000 в браузере — при `NEXT_PUBLIC_DEV_MODE=1` (включён в локальном
`.env`) приложение работает вне Telegram в режиме предпросмотра (создаётся технический «Гость»).
**Прод-сборка игнорирует dev-режим всегда** (`lib/dev-mode.ts` отсекает его по `NODE_ENV`
на этапе сборки): без валидного Telegram `initData` прод-бандл показывает только экран
«Открой приложение через Telegram» — даже если переменная случайно задана в прод-окружении.

Владельцам проекта — короткая инструкция из 5 команд: [SHORT-README.md](SHORT-README.md).

## Подключение Telegram-бота (без токена всё тоже работает)

1. **Получите BOT_TOKEN.** Откройте [@BotFather](https://t.me/BotFather) → `/newbot` →
   задайте имя и username → скопируйте токен вида `123456789:AA...` в `.env`:
   ```
   BOT_TOKEN="123456789:AA..."
   ```
2. **Создайте Mini App.** В @BotFather отправьте `/newapp`, выберите бота, задайте
   **short name** (например, `casegames`) и укажите публичный HTTPS-URL приложения.
   Short name сохраните в `.env` (`APP_SHORT_NAME="casegames"`) — бот будет присылать
   прямую ссылку вида `t.me/<bot_username>/<app_short_name>`.
3. **Пропишите публичный URL** приложения в `.env`:
   ```
   WEBAPP_URL="https://ваш-домен.ru"
   ```
   Для локальной разработки без домена подойдёт туннель:
   `cloudflared tunnel --url http://localhost:3000` или `ngrok http 3000`.
4. **Зарегистрируйте webhook и команды:**
   ```bash
   npm run tg:webhook
   ```
   Скрипт вызывает `setWebhook` (с `secret_token`), `setMyCommands` и `getMe`.
   Если `BOT_TOKEN` пуст — печатает эту же пошаговую инструкцию и выходит с кодом 0.

Команды бота: `/start` (кнопка «Открыть Кейс-игры» + прямая ссылка), `/app` (кнопка Mini App),
`/profile` (уровень, XP, серия, место в недельном топе), `/leaderboard` (топ-10 недели).

## Переменные окружения

Скопируйте `.env.example` → `.env` и заполните (секреты генерируются `openssl rand -hex 32`):

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | SQLite для разработки (`file:./dev.db`) или `postgresql://...` для прода |
| `BOT_TOKEN` | Токен @BotFather. Пусто → бот в mock-режиме, Mini App и API работают |
| `WEBAPP_URL` | Публичный URL Mini App (кнопка `web_app` + `setWebhook`) |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет webhook (заголовок `X-Telegram-Bot-Api-Secret-Token`) |
| `CRON_SECRET` | Защита `/api/cron/*` (`Authorization: Bearer ...` или `?secret=`) |
| `APP_SHORT_NAME` | Short name Mini App из `/newapp` — для прямой ссылки |
| `NEXT_PUBLIC_DEV_MODE` | `1` — вход в Mini App из браузера. Работает только в `next dev`; прод-сборка всегда игнорирует |

## AI-движок

- **Оценщик** `lib/evaluator.ts` — строгий системный промпт (анти-инъекция: пользовательский
  текст только внутри `<answer>…</answer>`), `temperature 0.3`, таймаут 60 с, при невалидном JSON
  ровно 1 повтор, zod-валидация (все критерии рубрики с точными именами, 0–10 баллов), поле
  `missed` («Что упущено», 2–4 пункта ≤ 12 слов, сверка со сценарием). Две неудачи →
  `Attempt.status = "failed"` (дружелюбный экран, без 500).
- **Генератор сценариев** `lib/scenario.ts` — стартовые условия конструктора/спасения
  (роль, ресурсы, ограничения, цель, риск-профиль, ровно 3 правила, скрытые missedFactors),
  `temperature 0.9`, zod, 1 повтор; после двух неудач — фолбэк на случайный статический кейс
  домена (режим никогда не падает). `missedFactors` не покидают сервер до отправки ответа.
- **Соперник** `lib/rival.ts` — генерируется ТОЛЬКО после ответа игрока; стили: Аналитик /
  Хастлер / Системщик (`temperature 0.8`, 600–1000 симв.), оценивается тем же оценщиком.

SDK `z-ai-web-dev-sdk` читает конфиг `~/.z-ai-config` (или `./.z-ai-config`):
```json
{ "baseUrl": "https://api.../v1", "apiKey": "..." }
```
**Если конфига нет, весь AI-движок работает в демо-режиме**: детерминированные эвристики,
честно помеченные `engine=mock` в `aiRaw`/API и плашкой в UI. Полный цикл (включая дуэли)
проходим локально без ключей; с конфигом включается настоящая LLM без изменений кода.

Правила продукта, реализованные в коде:
- **Квота — в раундах:** 3 бесплатных раунда в сутки (Europe/Moscow; раунд = попытка №1),
  «Три попытки» = 1 раунд; rate limit 30 попыток/сутки → 429; не-PRO за лимитом → 403 → экран PRO.
- **XP:** ≥85% → 60, ≥70% → 45, ≥50% → 30, иначе 15; +10 за первый раунд суток; повтор кейса
  в том же режиме → 0 XP; в «Трёх попытках» начисляется один раз по лучшей (прирост базы);
  победа в дуэли +20 XP; дрон с зарядом ≥ 60 даёт +10% к XP матча.
- **Рейтинг (Elo-лайт, старт 1000):** AI-дуэль +15/−10, PvP +20/−15, ничья при |Δ%| < 3,
  множитель сложности ×0.8/×1.0/×1.3; журнал RatingMatch. Лиги: Бронза < 1100, Серебро,
  Золото, Платина ≥ 1600 (третий таб лидерборда).
- **Серия:** активность сегодня — без изменений; вчера — +1; иначе сброс в 1.
- **Дрон:** день с матчем +15 (max 100), без матча −10, при 0 — «спячка»; первый вход без штрафа.
- **Приватность:** тумблер `profilePublic` — скрытый юзер отсутствует в топах/лигах/галерее,
  своя статистика полностью сохраняется.
- **Награды:** открываются за переход в лигу выше или 3 победы подряд в AI-дуэлях
  (`rewardsUnlockedAt`); карточки — заглушки «скоро».
- **Бейджи (12):** прежние 7 + `first_duel`, `duel_win_5`, `constructor_master`,
  `phoenix` (победа в «Спасении» ≥ 75%), `pitch_perfect` (питч ≥ 85%).
- **Безопасность:** рубрика/эталон/missedFactors не отдаются до ответа; ответы соперников
  скрыты до финала дуэли; ошибки LLM → `failed`/фолбэк без 500; чужие данные — 403/404.
- **Deep links:** вход по `startapp=duel_<id>` открывает дуэль сразу; PvP-ссылка
  `t.me/<bot>/<app>?startapp=duel_<id>` (нужны `APP_SHORT_NAME` + токен).

### Отклонения от ТЗ (осознанные)
- `Duel.rivalJson` и `Duel.difficulty` — доп. поля: ответ AI-соперника хранится в дуэли
  (у него нет пользовательского аккаунта), сложность нужна для множителя рейтинга.
- Лимит попыток раунда кодируется суффиксом roundId (`-a3`) — без лишней колонки в Attempt.
- Дуэли проводятся на статических кейсах (общий контент для честного сравнения соперников);
  конструктор-сценарии доступны в сольных раундах.
- `ReminderLog.type` — дедуп уведомлений 1/сутки на тип (серия / дрон).
- Prisma 6 вместо 7-й мажорной: v7 требует driver-адаптеров и `prisma.config.ts`;
  v6 даёт ту же схему с прямой переносимостью на PostgreSQL (без enum/Json типов).
- `NEXT_PUBLIC_DEV_MODE` — служебный вход для локального предпросмотра вне Telegram;
  действует только в `next dev` (`lib/dev-mode.ts` отсекает по `NODE_ENV` на сборке).

## Деплой (Node-хостинг или VPS)

Локально разработка идёт на SQLite (`DATABASE_URL=file:./dev.db`, `npm run db:push`).
Схема не использует SQLite-специфику; для продакшена — PostgreSQL:

```bash
# 1. Экспортируйте переменные из .env.example (на Vercel — в настройках проекта)
export DATABASE_URL="postgresql://user:password@host:5432/casegames"

# 2. Подготовьте БД: генерация pg-схемы, клиент, миграции (init + battles), сид
npm run pg:prepare
#    изменение схемы: правьте prisma/schema.prisma -> npm run pg:migrate -- --name <имя>

# 3. Соберите и запустите (клиент уже сгенерирован под PostgreSQL)
npm run build && npm start

# 4. Подключите бота и проверьте деплой
npm run tg:webhook
npm run deploy-check        # URL/HTTPS, /api/health, getMe, webhook
npm run deploy-check -- --start   # вариант: поднять next start локально и прогнать те же проверки
```

Как устроено: `prisma/schema.prisma` (SQLite) — единственный источник истины;
`npm run pg:schema` генерирует `prisma/schema.postgres.prisma` (provider заменён на
postgresql), миграции PostgreSQL живут в `prisma/migrations` и применяются только
pg-скриптами. После работы с PG-клиентом верните локальный клиент: `npx prisma generate`.
Публичный `/api/health` проверяет и приложение, и соединение с БД (для мониторов и deploy-check).
